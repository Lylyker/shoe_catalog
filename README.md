# ShoeCatalog — каталог обувной продукции

Информационно-поисковая система каталога обувной продукции с многокритериальной
фильтрацией на Python/Django + PostgreSQL. Учебный проект: учебная практика →
курсовая работа → подготовка к демонстрационному экзамену.

## Стек

- Python 3.12 (основная разработка) / Python 3.9.20
- Django 5.2 (main) / Django 4.2 LTS (ветка ДЭ)
- PostgreSQL + `psycopg2-binary`, `django-filter`
- Собственная дизайн-система `static/css/app.css` (без Bootstrap), vanilla JS
- Draw.io (ER-диаграмма, диаграммы классов, диаграмма активности), Git + GitHub

## Функциональность

- Каталог с фильтрацией по 10 критериям (категория, бренд, сезон, стиль, группа,
  страна, особенности, размер, цвет, цена), поиском и сортировкой; авто-применение по `onchange`.
- Индикация остатков «Много / Мало / Нет в наличии», подсветка дефицита (≤ 3).
- Динамическая скидка 25 % для товаров без заказов за отчётный период.
- Аутентификация по логину и паролю (режим курсовой) или только по логину
  (режим ДЭ, переключатель `REQUIRE_PASSWORD`).
- Регистрация с валидацией пароля, смена пароля, принудительная смена временного пароля.
- Личный кабинет: данные, история заказов, корзина, блок безопасности.
- Корзина и оформление заказа с фиксацией цены и списанием остатков со складов.
- Отзывы с рейтингом, сводкой и распределением оценок.
- Роли: Покупатель / Менеджер / Администратор.
- Панель управления `/manage/`: товары и варианты, справочники, пользователи и роли,
  заказы (добавить/удалить позицию, изменить), поставки (создать/провести/отменить),
  остатки и журнал движений, массовое удаление — всё без захода в `/admin`.
- Складской учёт: поставщики, склады, поставки с позициями, остатки по складам,
  журнал движений; проведение и отмена поставки с контролем остатков.
- `SafeFileSystemStorage` и глобальный санитайзер суррогатных символов
  (корректная работа с кириллическими именами файлов).
- Собственные системные проверки Django (`core.W001`, `core.W002`),
  команда `check_encoding`, git pre-commit hook.
- Плотность интерфейса (Авто / S / M / L) и вёрстка, устойчивая к масштабированию
  браузера до 500 %.

## Запуск

| Шаг | Команда | Описание |
|-----|---------|----------|
| 1 | `git clone https://github.com/Lylyker/shoe_catalog.git && cd shoe_catalog` | Клонировать репозиторий |
| 2 | `python -m venv .venv312` | Создать виртуальное окружение |
| 3 | `source .venv312/bin/activate` | Активировать окружение |
| 4 | `pip install -r requirements.txt` | Установить зависимости |
| 5 | `createdb -U postgres -h 127.0.0.1 shoe_catalog_db` | Создать базу данных |
| 6 | `python manage.py migrate` | Применить миграции |
| 7 | `python manage.py seed_data` | Наполнить БД тестовыми данными |
| 8 | `python manage.py load_product_images` | Загрузить фото товаров |
| 9 | `python manage.py init_passwords` | Выдать временные пароля |
| 10 | `python manage.py init_stock && python manage.py seed_supply` | Завести склады и демо-поставки |
| 11 | `python manage.py createsuperuser` | Создать суперпользователя |
| 12 | `python manage.py runserver` | Запустить сервер: http://127.0.0.1:8000/ |

> Вместо шагов 6–10 можно восстановить готовый бэкап из `backup/` (см. «База данных»).

## Аутентификация и пароли

- Переключатель режимов в `settings.py`: `REQUIRE_PASSWORD = True` (курсовая,
  логин + пароль) / `False` (ДЭ, только логин, как требует КИМ).
- Маршруты: `/login/`, `/register/`, `/profile/`, `/password/change/`, `/logout/`.
- Пароли проверяются стандартными валидаторами Django: не короче 8 символов,
  не только цифры, не совпадают с логином или ФИО.
- Пользователи без пароля (созданные до введения модуля) получают временный пароль
  через `init_passwords` и обязаны сменить его при первом входе.
- Смена пароля выполняется через `update_session_auth_hash` — сессия не разрывается.

### Резервная копия

В `backup/` лежат два дампа, созданные `pg_dump`:
- `shoe_catalog.dump` — сжатый custom-формат (восстановление через `pg_restore`);
- `shoe_catalog.sql` — читаемый plain SQL (восстановление через `psql`).

Оба содержат полную структуру и все данные и позволяют полностью восстановить систему.

Создание бэкапа:

```bash
pg_dump -U postgres -h 127.0.0.1 -d shoe_catalog_db -F c -f backup/shoe_catalog.dump
pg_dump -U postgres -h 127.0.0.1 -d shoe_catalog_db -f backup/shoe_catalog.sql
```

### Загрузка бэкапа

```bash
# 1. пустая БД (или перезапись существующей)
dropdb -U postgres -h 127.0.0.1 shoe_catalog_db
createdb -U postgres -h 127.0.0.1 shoe_catalog_db
# 2. восстановление (custom-формат)
pg_restore -U postgres -h 127.0.0.1 -d shoe_catalog_db --clean --if-exists backup/shoe_catalog.dump
#    либо plain SQL:
psql -U postgres -h 127.0.0.1 -d shoe_catalog_db -f backup/shoe_catalog.sql
# 3. проверка
psql -U postgres -h 127.0.0.1 -d shoe_catalog_db -c "SELECT count(*) FROM catalog_product;"
python manage.py migrate && python manage.py runserver
```

### Типичные проблемы

| Проблема | Решение |
|----------|---------|
| `database "shoe_catalog_db" does not exist` | Создать БД командой `createdb` |
| `permission denied for database` | Проверить права пользователя postgres |
| `relation "catalog_product" does not exist` | База пустая: восстановить дамп или `migrate` + `seed_data` |
| Ошибки кодировки при восстановлении | Создать БД с UTF-8: `createdb -E UTF-8 shoe_catalog_db` |

## Складской учёт и поставки (приложение `supply`)

Модели: `Supplier`, `Warehouse`, `Supply` (шапка), `SupplyItem` (позиции),
`StockBalance` (остаток варианта на складе), `StockMovement` (журнал движений),
`StatusSupply` (черновик / проведена / отменена).

Правила учёта:

- `ProductVariant.quantity` — агрегат: сумма остатков по всем складам (`StockBalance`).
- Проведение поставки (`post_supply`) увеличивает остатки; доступно только для черновика.
- Отмена проведённой поставки (`cancel_supply`) списывает остатки и блокируется,
  если часть товара уже продана.
- Оформление заказа списывает товар со складов от большего остатка к меньшему
  (`consume_stock`) и пишет движения с основанием «Заказ».
- Удаление позиции заказа возвращает товар строго на те склады, откуда он был списан
  (`return_stock_for_order`), по данным журнала движений.
- Все складские операции атомарны (`transaction.atomic` + `select_for_update`).

## Целостность данных и кодировка (приложение `core`)

Многоуровневая защита от суррогатных символов (`surrogateescape`), из-за которых
PostgreSQL отклоняет запись (`UnicodeEncodeError: surrogates not allowed`):

| Слой | Механизм |
|------|----------|
| Исходники | `python manage.py check_encoding` + git pre-commit hook |
| ORM | Глобальный сигнал `pre_save`: санитайзер всех текстовых и файловых полей |
| Файлы | `SafeFileSystemStorage`: очистка имён во всех точках входа |
| Окружение | `manage.py` перезапускает процесс в UTF-8-режиме (`PYTHONUTF8=1`) |
| Диагностика | Системные проверки `core.W001` (кодировка ФС), `core.W002` (хранилище) |

Включение hook:

```bash
git config core.hooksPath .githooks
```

## Интерфейс и масштабирование

- Единая дизайн-система `static/css/app.css`; Bootstrap не используется.
- `static/js/ui.js`: переключатель плотности (Авто / S / M / L), плотность строк
  таблиц, липкие заголовки, повышенный контраст, отключение анимации, скрытие меню;
  настройки сохраняются в `localStorage`.
- Режим «Авто» подбирает масштаб по эффективной ширине окна, поэтому интерфейс
  остаётся читаемым при масштабировании браузера до 500 %.
- Все таблицы получают собственный горизонтальный скролл, блоки с фиксированной
  шириной автоматически ограничиваются контейнером.
