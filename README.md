# ShoeCatalog — каталог обувной продукции

Информационно-поисковая система каталога обувной продукции с многокритериальной
фильтрацией на Python/Django + PostgreSQL.

## Стек
Python 3.11, Django 5.2, PostgreSQL, django-filter, Bootstrap 5, Bootstrap-иконки, Lucide-иконки.

## Функциональность
- Каталог товаров с фильтрацией (категория, бренд, сезон, стиль, группа, страна,
  свойства, размер, цвет, цена), поиском и сортировкой (авто-применение по onchange).
- Индикация остатков: «Много» / «Мало» / «Нет в наличии», подсветка дефицита (≤3).
- Динамическая скидка 25% для товаров без заказов за отчётный период.
- Авторизация по логину, регистрация с ролью «Покупатель», личный кабинет.
- Корзина, оформление заказа с фиксацией цены и списанием остатков.
- Отзывы с рейтингом и распределением оценок.
- Роли: Покупатель / Менеджер / Администратор; управление заказами, удаление
  позиций с возвратом остатка (админ).
- SafeFileSystemStorage — корректная работа с кириллическими именами файлов.

## Запуск

| Шаг | Команда | Описание |
|-----|---------|----------|
| 1 | `git clone https://github.com/Lylyker/shoe_catalog.git && cd shoe_catalog` | Клонировать репозиторий и перейти в папку проекта |
| 2 | `python -m venv myvenv` | Создать виртуальное окружение |
| 3 | `source myvenv/bin/activate` | Активировать виртуальное окружение |
| 4 | `pip install -r requirements.txt` | Установить зависимости |
| 5 | `createdb -U postgres -h 127.0.0.1 shoe_catalog_db` | Создать базу данных PostgreSQL |
| 6 | `python manage.py migrate` | Применить миграции (создать таблицы) |
| 7 | `python manage.py seed_data` | Наполнить БД тестовыми данными |
| 8 | `python manage.py load_product_images` | Загрузить фото товаров |
| 9 | `python manage.py createsuperuser` | Создать суперпользователя для `/admin/` |
| 10 | `python manage.py runserver` | Запустить сервер: http://127.0.0.1:8000/ |

> Вместо шагов 6–8 можно восстановить готовый бэкап из папки `backup/` (см. раздел «База данных»).

## База данных

Система использует СУБД **PostgreSQL**. Параметры подключения задаются в
`shoe_catalog/settings.py` (блок `DATABASES`):

| Параметр | Значение |
|----------|----------|
| Имя БД | `shoe_catalog_db` |
| Пользователь | `postgres` |
| Хост | `127.0.0.1` |
| Порт | `5432` |
| Драйвер | `psycopg2` |

Схема БД создаётся миграциями Django, данные наполняются командой `seed_data`.

### Резервная копия

В папке `backup/` хранятся два дампа, созданные утилитой `pg_dump`:
- `shoe_catalog.dump` — сжатый custom-формат (восстановление через `pg_restore`);
- `shoe_catalog.sql` — читаемый plain SQL (восстановление через `psql`).

Оба файла содержат полную структуру БД и все данные (справочники, товары,
пользователи, заказы, отзывы) и позволяют полностью восстановить работоспособную систему.

### Бэкап:


Создание бэкапа

- `pg_dump -U postgres -h 127.0.0.1 -d shoe_catalog_db -F c -f backup/shoe_catalog.dump`
- `pg_dump -U postgres -h 127.0.0.1 -d shoe_catalog_db -f backup/shoe_catalog.sql`

Загрузка бэкапа

Для восстановления базы данных из резервной копии выполните следующие шаги:

**Шаг 1. Создание пустой базы данных**

- `createdb -U postgres -h 127.0.0.1 shoe_catalog_db`

Если база уже существует и нужно её полностью перезаписать:

- `dropdb -U postgres -h 127.0.0.1 shoe_catalog_db`
- `createdb -U postgres -h 127.0.0.1 shoe_catalog_db`

**Шаг 2. Восстановление из custom-формата (рекомендуется)**

- `pg_restore -U postgres -h 127.0.0.1 -d shoe_catalog_db --clean --if-exists backup/shoe_catalog.dump`

Параметры:

    --clean — удаляет существующие объекты перед восстановлением
    --if-exists — не выдаёт ошибку, если объект не существует

**Шаг 3. Альтернативное восстановление из SQL-файла**

- `psql -U postgres -h 127.0.0.1 -d shoe_catalog_db -f backup/shoe_catalog.sql`

**Шаг 4. Проверка восстановления**

- `psql -U postgres -h 127.0.0.1 -d shoe_catalog_db -c "SELECT count(*) FROM catalog_product;"`
- `psql -U postgres -h 127.0.0.1 -d shoe_catalog_db -c "SELECT count(*) FROM users_user;"`

**Шаг 5. Запуск сервера**

- `python manage.py runserver`
